# dzahdev.recom - персональные рекомендации товаров для 1С-Битрикс

Модуль записывает действия покупателей (просмотр, корзина, отложенный товар, покупка), обучает на
них модели рекомендаций на чистом PHP и выводит персональные, похожие и популярные товары на сайте
и в письмах. Внешних сервисов, Docker и composer модуль не требует.

## 1. Модели

| Модель | Назначение | Источник |
|---|---|---|
| ALS для неявных сигналов (покоординатный спуск с кешем матрицы Грама) | персональные оценки "покупатель - товар" | X. He et al., Fast Matrix Factorization for Online Recommendation with Implicit Feedback, SIGIR 2016; Y. Hu, Y. Koren, C. Volinsky, ICDM 2008 |
| Сходство товаров: косинус с весами IDF и сжатием n/(n + 100) | блок "Похожие", кандидаты подборок | J. Breese, D. Heckerman, C. Kadie, UAI 1998 (IDF); Y. Koren, KDD 2008 (сжатие) |
| Популярное за окно | общий рейтинг и рейтинг по разделам | сумма весов сигналов |
| Factorization machine второго порядка | ранжирование кандидатов персональной подборки по признакам "покупатель, товар, раздел" | S. Rendle, Factorization Machines, ICDM 2010 |
| NDCG@10 на отложенной выборке | метрика качества ALS и FM | K. Jarvelin, J. Kekalainen, ACM TOIS 2002 |

## 2. Требования

- PHP 8.1 или новее; модули `iblock`, `catalog`, `sale`.
- Агенты на cron (константа `BX_CRONTAB_SUPPORT` в `dbconn.php`) либо регулярный запуск
  `tools/train.php` из cron. На хитах обучение не выполняется.

## 3. Установка и удаление

1. Скопировать модуль в `/local/modules/dzahdev.recom/`.
2. "Marketplace - Установленные решения" - "Персональные рекомендации" - "Установить".

Установка создает таблицы `b_dzahdev_recom_*`, регистрирует обработчики событий, агенты
`TrainAgent` (раз в час) и `CleanupAgent` (раз в сутки), копирует JS-расширение и компоненты в
`/bitrix/`. Удаление удаляет таблицы вместе с событиями и обученными моделями, настройки модуля,
обработчики, агенты и скопированные файлы.

## 4. Сбор событий

| Тип | Источник |
|---|---|
| `view` | ORM-события `\Bitrix\Catalog\CatalogViewedProduct::OnAfterAdd` и `::OnAfterUpdate` (запись `CatalogViewedProductTable::refresh()` из карточки товара) |
| `cart` | `sale:OnSaleBasketItemSaved`, новая позиция или перенос из отложенных |
| `delay` | `sale:OnSaleBasketItemSaved`, `DELAY = Y` |
| `buy` | `sale:OnSaleOrderSaved`, новый заказ, событие на каждую позицию |

Покупатель - `FUSER_ID`. Торговое предложение приводится к родительскому товару. Обработчик только
добавляет строку в `b_dzahdev_recom_event`; ошибка учета пишется в журнал событий
(`DZAHDEV_RECOM_TRACKING`) и не прерывает работу корзины и заказа.

Для шаблонов карточки без стандартного учета просмотров:

```js
BX.loadExt('dzahdev.recom').then(() => DzahdevRecom.trackView(productId));
```

Ответ `{recorded: true}`; `false` - элемент не входит в торговый каталог.

## 5. Обучение

Из корня сайта:

```bash
php local/modules/dzahdev.recom/tools/train.php          # дообучение
php local/modules/dzahdev.recom/tools/train.php --full   # полное обучение с NDCG@10
```

Код выхода 0 - обучение выполнено, 1 - ошибка (текст в stderr). На сайтах с Symfony Console
(composer) та же операция - `php bitrix/bitrix.php dzahdev.recom:train [--full]`.

Скрипт запускается от пользователя веб-сервера, например в crontab этого пользователя:

```bash
0 * * * * cd /var/www/site && php local/modules/dzahdev.recom/tools/train.php
```

Запуск от root создает в `bitrix/managed_cache` файлы, которые сайт не может перезаписать: после
этого изменения настроек модуля в админке читаются из устаревшего кеша.

- Дообучение: ALS стартует с сохраненных векторов, 3 эпохи; похожие, популярное, FM и подборки
  пересчитываются.
- Полное обучение: ALS с нуля, 20 эпох; NDCG@10 для ALS и FM на отложенной выборке (последний товар
  каждого покупателя).
- Агент `TrainAgent` запускает полное обучение раз в `train_full_interval` секунд или по флагу
  "Обучить сейчас", в остальных запусках - дообучение.
- Параллельный запуск блокируется (`Connection::lock`); второй запуск завершается ошибкой
  `Training is already running`.
- Каждый прогон пишется в `b_dzahdev_recom_train_log`: режим, длительность, размеры данных,
  NDCG@10 ALS и FM, текст ошибки.

## 6. Вывод на сайте

```php
$APPLICATION->IncludeComponent('dzahdev:recom.list', '', [
	'MODE' => 'personal',      // personal | similar | popular
	'IBLOCK_ID' => 2,          // инфоблок каталога
	'PRODUCT_ID' => 0,         // для similar
	'SECTION_ID' => 0,         // для popular, 0 - весь каталог
	'COUNT' => 8,
	'PRICE_CODE' => ['BASE'],
	'SECTION_TEMPLATE' => '.default',  // шаблон bitrix:catalog.section
]);
```

Компонент получает список ID и выводит его через `bitrix:catalog.section` с сортировкой
`CUSTOM_ELEMENT_SORT`. Атрибут `data-source` блока - источник выдачи.

Цепочка режима `personal`: готовая подборка (FM или ALS) -> похожие на последние товары
покупателя -> популярное. Исключаются купленные товары и позиции текущей корзины.

JSON-выдача: `BX.ajax.runAction('dzahdev:recom.Recommend.getList', {data: {mode, productId, sectionId, count}})`
возвращает `{ids: [...], source: 'personal' | 'similar' | 'popular'}`.

## 7. Письма

В HTML-шаблоне почтового события:

```php
<?EventMessageThemeCompiler::includeComponent("dzahdev:recom.list.mail", "", Array(
	"MODE" => "personal",
	"USER_ID" => "{#USER_ID#}",
	"COUNT" => "4",
))?>
```

- `MODE` `similar` принимает `PRODUCT_ID` (например `{#PRODUCT_ID#}`), `popular` - `SECTION_ID`.
- Получатель определяется по `USER_ID` чтением `FuserTable` без создания корзины покупателя;
  получатель без истории получает популярное.
- Отрисовка - стандартный `bitrix:catalog.show.products.mail`. Абсолютные ссылки строятся из поля
  "URL сервера" сайта ("Настройки - Сайты").
- `MODE = similar` без `PRODUCT_ID` - исключение `SystemException`, письмо не отправляется.

## 8. Настройки

"Настройки - Настройки модулей - Персональные рекомендации". Значения по умолчанию
(`default_option.php`):

| Настройка | По умолчанию |
|---|---|
| Положительные типы событий | `view, cart, delay, buy` |
| Веса `view / delay / cart / buy` | `1 / 2 / 3 / 5` |
| ALS: факторы, `reg`, `alpha`, эпохи полного / дообучения | `16`, `0.06`, `0.001`, `20 / 3` |
| FM: включена, факторы, шаг, `reg`, эпохи, отрицательных примеров | `Y`, `8`, `0.05`, `0.0001`, `30`, `2` |
| Минимум товаров для персональной подборки | `3` |
| Длина подборки / похожих / популярного | `50 / 20 / 100` |
| Окно популярного, дней | `30` |
| Подборки для покупателей, активных за дней | `30` |
| Срок хранения событий, дней | `180` |
| Покупателей в оценке NDCG@10 | `300` |
| Максимум товаров истории для расчета похожих | `500` |
| Полное обучение не реже, секунд | `86400` |

Вкладка "Статистика": число событий, покупателей, товаров, последний прогон. Кнопка "Обучить
сейчас" ставит флаг полного обучения для ближайшего запуска агента или скрипта.

## 9. Тесты и замеры

```bash
php local/modules/dzahdev.recom/tests/run.php     # 55 тестов математики без ядра Битрикса
php local/modules/dzahdev.recom/tests/bench.php   # замер на синтетике
```

Замер (PHP 8.2 без JIT, 97 541 пара, 5 000 покупателей, 1 000 товаров): ALS 20 эпох - 12 с,
похожие товары - 0.4 с, FM 30 эпох на 292 623 примерах - 35 с, пиковая память 182 МБ.

Ограничение: FM держит все обучающие примеры в памяти (около 180 МБ на 100 тысяч событий), при
`memory_limit` 512 МБ это порядка 300 тысяч событий за срок хранения.
